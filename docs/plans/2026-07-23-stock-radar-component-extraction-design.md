# 股票雷达组件渐进提取设计

日期：2026-07-23

## 目标与边界

在不改变页面行为、分析数据结构、排序规则、评分逻辑和视觉表现的前提下，降低 `App.jsx` 中股票雷达模块的复杂度。

本阶段只处理展示组件与纯 UI 数据准备，不调整 Serenity 分析、证据提取、每日判断生成、Dashboard 合同或行情投影结构。

## 方案比较

### 方案 A：整体迁移 StockRadarDashboard

可以一次减少数百行，但该组件依赖大量当前文件内的研究函数、文案映射和展示工具。整体迁移会形成大范围依赖搬迁，回归面过大。暂不采用。

### 方案 B：提取无状态展示组件

推荐并采用。页面容器继续负责筛选、选中状态和研究数据计算；页头、筛选栏、股票列表、每日复盘等组件只接收已经准备好的属性。这可以逐步缩小 JSX，同时不改变数据流。

### 方案 C：重写为全新页面架构

长期结构最整齐，但会同时改变组件边界、状态管理和样式作用域，不符合本轮“无行为重构”的目标。不采用。

## 组件边界

```text
StockRadarDashboard
  ├─ StockRadarHero
  ├─ StockRadarToolbar
  ├─ StockRadarList
  ├─ StockRadarDetail
  │   ├─ StockRadarQuoteSummary
  │   └─ StockRadarDailyReview
  └─ EmptyState
```

本轮优先提取：

- `StockRadarHero`：方向标题、深研数量和更新时间。
- `StockRadarToolbar`：方向切换、搜索和排序说明。
- `StockRadarList`：股票卡片列表与选中回调。
- `StockRadarDailyReview`：复盘状态、指标、判断变化和自动关注项。

复杂的证据卡片、趋势图和行业阶段判断继续保留在页面容器，避免一次迁移过多研究逻辑。

## 样式策略

本轮不整体移动现有 CSS 规则。新组件继续使用原 className，因此视觉和响应式行为保持不变。等组件边界稳定后，再按组件提取 CSS；这样能避免当前样式文件中的层叠顺序发生变化。

## 验证

- 组件提取前后 DOM 语义和可访问名称保持一致。
- 股票排序、行业切换、搜索、选中详情和每日复盘内容不变。
- 单元测试、数据校验和生产构建通过。
- 浏览器回归覆盖股票雷达、行业切换、搜索和其他四个主导航入口。
