# Dashboard 页面按需加载设计

日期：2026-07-23

## 目标与边界

降低首页 JavaScript 主包体积，让数据库页面使用的大型研究材料只在用户进入“数据库”时加载。

本阶段不修改 Dashboard JSON 内容、Serenity 分析结构、评分逻辑、行情投影或页面业务规则。只调整模块边界和浏览器加载时机。

## 体积现状

当前生产主包约 5.46MB。数据库页直接依赖的主要数据包括：

- `serenity_materials.json`：约 2.5MB
- `serenity_analysis.json`：约 1MB
- `review_cycle.json`：约 700KB
- `sources.json`：约 500KB
- 其他研究门禁、候选漏斗和 Bridge 数据

这些数据即使用户只看股票雷达，也会被静态打入首页主包。

## 方案比较

### 方案 A：所有 JSON 改为 fetch

主包最小，但需要同时引入加载、缓存、失败、竞态和数据合同校验，改动面过大。不作为第一步。

### 方案 B：使用动态页面模块

推荐并采用。将数据库页面与其专属 JSON import 移到独立模块，通过 `React.lazy` 仅在进入数据库时加载。股票雷达已有数据流保持不变。

### 方案 C：只调整 Rollup manualChunks

可以改变产物文件名，但静态依赖仍会在首页立即请求，不能实现真正的按页面加载。不采用。

## 模块结构

```text
App
  ├─ 股票雷达（首页立即加载）
  ├─ 公司
  ├─ 市场
  ├─ 时间轴
  └─ lazy DatabasePage
       ├─ serenity materials
       ├─ serenity analysis
       ├─ research gates
       ├─ review cycle
       ├─ sources
       └─ database-only UI helpers
```

`serenity_outputs` 同时服务股票雷达和数据库，因此本阶段仍由首页持有，并作为属性传给数据库页面，避免重复加载或形成共享首屏分包。

## 加载与错误处理

- 数据库模块加载期间显示与现有页面风格一致的加载状态。
- 动态模块加载失败时显示错误说明和重新加载按钮。
- 切换到其他主导航不受数据库模块加载状态影响。
- 数据库页面加载完成后继续使用原有证据抽屉回调。

## 验证

- 比较改造前后的 Vite 构建产物。
- 首页、行业切换、搜索和股票详情保持不变。
- 首次进入数据库时能完成动态分包加载。
- 公司、市场、时间轴导航正常。
- 数据校验、单元测试和生产构建通过。
