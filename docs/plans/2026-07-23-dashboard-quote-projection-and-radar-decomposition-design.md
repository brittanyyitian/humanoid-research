# Dashboard 最新行情投影与股票雷达渐进拆分设计

日期：2026-07-23

## 目标与边界

解决同一只股票在列表、详情和趋势区域显示不同价格的问题，同时降低股票雷达页面继续扩展的维护成本。

本次不修改 Serenity 的分析结构、评分逻辑、证据结构、历史分析文件或判断历史。`data/analysis/serenity_outputs/*.json` 中的行情继续表示生成分析时使用的记录行情，保证历史判断可以复现。

## 方案比较

### 方案 A：覆盖分析结果中的行情

实现最简单，但会破坏历史判断的可复现性。分析生成时使用的价格会被当天行情替换，无法回答“当时为什么得出这个判断”。不采用。

### 方案 B：仅在 React 页面临时关联 market.json

改动较小，但每个页面都可能形成自己的行情选择规则，生成的 Dashboard 数据本身仍然不一致，也不利于后续校验。作为兼容回退保留，不作为主方案。

### 方案 C：Dashboard 投影层组合，前端统一消费

推荐并采用。生成 `data/dashboard/serenity_outputs.json` 时，为每条分析输出附加：

- `analysisQuote`：分析文件中的原始记录行情。
- `latestQuote`：目标日期的最新市场快照。
- `quoteStatus`：两个时间点和是否过期。

原有 `display.stockRadar.quote` 保持不变，以兼容现有消费者。前端通过统一适配器选择 `latestQuote`，缺失时回退 `analysisQuote`。

## 数据流

```text
原始 Serenity 分析（不改）
        +
目标日期 market 快照
        |
generate-dashboard 投影
        |
analysisQuote / latestQuote / quoteStatus
        |
股票雷达行情适配器
        |
列表、详情、每日复盘展示
```

列表中的现价、涨跌幅和成交额统一使用 `latestQuote`。详情同时展示“最新价”和“分析记录价”，避免把实时行情与分析时点混为一谈。判断、评分、证据、触发条件和趋势分析文本仍来自原始 Serenity 输出。

## 前端拆分

本轮采用渐进拆分，不整体搬迁四千行的 `App.jsx`：

1. 新建 Serenity 行情适配模块，集中处理最新行情、回退、时间和过期状态。
2. 新建股票雷达行情摘要组件，负责最新价与分析记录价的展示。
3. `StockRadarDashboard` 保留页面编排和现有研究逻辑。

后续可继续拆分卡片列表、详情证据、趋势和每日复盘，但不与本次数据正确性修复绑定。

## 校验与失败处理

- Dashboard 生成时，如果存在目标日期行情，则 `latestQuote.price` 必须与 `market.json` 同实体价格一致。
- `analysisQuote` 不得因行情投影而变化。
- 最新行情缺失时，页面回退分析行情，并显示“分析记录行情”，不伪装为最新行情。
- 构建、数据校验和浏览器回归需要覆盖股票雷达、公司、市场、时间轴和数据库五个入口。
