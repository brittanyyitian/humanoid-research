# 公司、市场与时间轴页面按需加载设计

## 目标

在股票雷达已经完成数据级拆包的基础上，将非首屏的公司、市场和时间轴页面移出主脚本，同时保持页面内容、公司跳转、行情证据和证据抽屉行为不变。

成功标准：

- 股票雷达首屏不再加载完整公司集合、公司行情页代码和时间轴数据。
- 从市场点击公司后，仍能进入对应公司的详情。
- 公司页的事件、Follow-up、来源和行情证据保持一致。
- 市场页的涨幅榜、成交额榜和全部股票卡片保持一致。
- 时间轴节点和证据抽屉保持一致。
- 页面加载失败有明确的重试入口。

## 方案比较

### 方案一：仅配置打包分组

实现最少，但静态依赖仍由首屏引用，浏览器仍会在启动时下载，不能真正减少首屏数据。

### 方案二：三个页面完全独立

边界最直观，但公司页和市场页都会引用同一份公司及行情数据，容易生成重复块或增加维护成本。

### 方案三：公司与市场共享延迟模块，时间轴独立

公司和市场天然共享公司集合、行情格式化、股票卡片和证据构造，因此放入同一个延迟模块。时间轴只有独立的时间轴数据和节点组件，单独拆分。采用此方案。

## 架构与数据流

- `CompanyMarketPages.jsx` 导出 `CompanyPage` 和 `MarketPage`，模块内部读取公司与行情数据，并复用同一套股票卡片、事件卡片和证据构造函数。
- `TimelinePage.jsx` 读取时间轴数据并渲染节点。
- `App.jsx` 只保留导航状态、跨页公司 ID、证据抽屉和股票雷达。
- 公司 ID 初始为 `null`，公司模块加载后按原规则选择首个上市公司；从市场打开公司时仍由顶层保存指定 ID。
- 页面通过 `React.lazy` 与 `Suspense` 加载。加载失败时展示对应页面名称和重新加载按钮。

首屏日期和生成时间改用已经静态加载的 `serenity_output_index.json` 元数据，避免为两个简单字段继续加载完整 `today.json`。两者来自同一次 Dashboard 生成任务，日期口径一致。

## 验证

- 构建前后记录主脚本及各页面块大小。
- 浏览器依次验证股票雷达、公司、市场、时间轴、数据库。
- 从市场卡片进入指定公司，并打开行情证据。
- 打开时间轴和公司事件证据抽屉。
- 运行单元测试、数据校验、硬化检查和生产构建。
- 检查浏览器控制台无错误或警告。
